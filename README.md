# Мир Сонечки

Персональное игровое мобильное веб-приложение для девятилетней Сони: коллекция питомцев,
задания, монеты, магазин наград, достижения и родительский режим для мамы.

## Быстрый старт (локальный демо-режим)

```bash
npm install
npm run dev        # режим разработки → http://localhost:5173
# или
npm run build && npm run preview   # production-сборка → http://localhost:4173
```

Без ключей Supabase приложение работает в **Local Demo Mode**: все данные хранятся локально
в IndexedDB этого браузера и никуда не отправляются.

- Профиль Сони создаётся автоматически при первом запуске: имя Соня, уровень 1, 100 монет.
- Родительский режим: «Это я!» → «Настройки для мамы», **PIN по умолчанию `1234`**
  (смена: Настройки для мамы → Родительская панель → Финансы → «Сменить PIN»).
- Сброс игры: «Это я!» → Настройки для мамы → «Сбросить демонстрационные данные».

## Стек

React 18 · TypeScript · Vite · Tailwind CSS · Lucide Icons · vite-plugin-pwa · IndexedDB ·
Supabase (опционально).

## Структура проекта

```
src/
  types.ts               # типизированные модели данных
  services/
    db.ts                # promise-обёртка над IndexedDB (атомарный batch)
    store.ts             # центральный сервис данных и бизнес-логики (экономика, идемпотентность)
    seed.ts              # демонстрационные данные (помечены Demo)
    achievements.ts      # определения и проверка достижений
    catalog.ts           # валидация импорта JSON-каталога
    sound.ts             # синтезированные звуки (по умолчанию выключены)
    online.ts / cloud.ts # индикатор сети / опциональный клиент Supabase
  state/AppContext.tsx   # глобальное состояние, тосты, поздравления с достижениями и уровнями
  components/            # UI-кит (ui.tsx) и генеративная SVG-графика (art.tsx)
  screens/               # Главная, Коллекция, Квесты, Магазин, Профиль
  screens/parent/        # Родительская панель: Обзор, Задания, Награды, Финансы + PIN-вход
supabase/schema.sql      # схема БД, RLS и атомарные RPC-функции
```

## Основные сценарии (проверены)

1. Создание питомца — Коллекция → «+» → форма «Мой питомец» (фото сжимается до 640px).
2. Изменение статуса питомца — карточка → «Не найден / Хочу получить / Есть у меня».
3. Фильтрация и поиск коллекции — фильтры + строка поиска по имени.
4. Создание задания — родитель: Задания → «Новое» (категория, сложность, награда).
5. Отправка задания — ребёнок: Квесты → «Выполнить» → комментарий/фото → маме.
6. Подтверждение родителем — родитель: Задания → «Проверить» → «Подтвердить».
7. Начисление монет — происходит только на шаге 6, атомарно с записью в журнал.
8. Повторное начисление невозможно — защита по `referenceId` транзакции + статус заявки.
9. Заявка на награду — Магазин → «Обменять» → «Подтвердить» (монеты НЕ списываются).
10. Подтверждение заявки — родитель: Награды → «Решить» → «Одобрить» → списание → «Выдано».
11. Списание монет — только при одобрении; отрицательный баланс запрещён.
12. Сохранение данных — IndexedDB; перезагрузка/закрытие вкладки ничего не теряет.

## Механика яиц (как в «Укради яйцо»)

- Найденные существа живут в альбоме; ненайденные показаны **затемнённым яйцом** — имя,
  описание, характеристики и привычки скрыты («???»).
- Яйцо покупается в магазине за монеты (вкладка «Яйца», цена зависит от редкости: 10–500).
  Покупка списывает монеты сразу, без подтверждения родителя.
- Яйца продаются **по редкости** (сюрприз-яйца): внутри случайное существо выбранной редкости.
  Пока у Сони есть ненайденные существа этой редкости — выпадает всегда новое; когда все найдены,
  начинают выпадать **вариации**: то же существо с новым именем (например, «Кристальный ежик»
  вместо «Росистого ежика»), перекрашенным визуалом, другими характеристиками, описанием и привычками.
- Купленное яйцо попадает в «Питомцы». На его странице кнопка **«Растить яйцо!»**
  запускает таймер вылупления, который зависит от редкости:

  | Редкость | Время | | Редкость | Время |
  |---|---|---|---|---|
  | Обычная | 5 мин | | Космическая | 1 день |
  | Необычная | 15 мин | | Секретная | 2 дня |
  | Редкая | 30 мин | | Вечная | 4 дня |
  | Эпическая | 1 час | | Божественная | 7 дней |
  | Легендарная | 4 часа | | Мифическая | 12 часов |

- Таймер тикает, пока приложение открыто; если закрыть — яйцо вылупится при следующем запуске.
  Вылупление: конфетти, звук, раскрытие имени, описания, характеристик и любимых привычек.

## Экономика

- Простое задание: 5 · среднее: 10–15 · сложное: 20 · особенное: 30–50 монет.
- Каждая операция журналируется: сумма, тип, описание, дата, инициатор, уникальный `referenceId`.
- Ручная корректировка (только родитель) требует сумму и причину; минус запрещён.
- Уровень: 100 опыта за уровень, опыт начисляется за подтверждённые задания.

## Импорт каталога питомцев

«Это я!» → Настройки для мамы → «Импорт каталога питомцев» → вставить JSON-массив:

```json
[
  {
    "id": "unique-id",
    "name": "Pet name",
    "rarity": "Rare",
    "category": "Animal",
    "description": "Description",
    "imageUrl": null,
    "source": "Steal an Egg",
    "sourceVerified": false
  }
]
```

Редкость — одна из: `Обычная, Необычная, Редкая, Эпическая, Легендарная, Мифическая, Космическая, Секретная, Вечная, Божественная` (старые английские названия тоже принимаются и переводятся автоматически).
Импортёр проверяет поля и пропускает дубликаты (по `id` и имени). Встроенный демо-каталог —
вымышленные существа с пометкой **Demo**, их можно дополнить или заменить настоящим каталогом
без переписывания приложения.

## Настройка Supabase (облачный режим) — опционально

1. Создайте проект на [supabase.com](https://supabase.com).
2. Откройте **SQL Editor** → выполните скрипт `supabase/schema.sql`
   (таблицы, индексы, RLS, атомарные функции `approve_quest_submission` и `approve_reward_request`).
3. **Settings → API**: скопируйте Project URL и anon key.
4. Скопируйте `.env.example` в `.env.local` и заполните:

```bash
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

5. Пересоберите. Индикатор в шапке переключится с «Локально» на «Онлайн».

> Текущая версия выполняет всю бизнес-логику в Local Data Provider. Схема, RLS и RPC-функции
> Supabase подготовлены для облачной синхронизации — перенос слоя `services/store.ts` на
> `services/cloud.ts` (клиент уже подключается по env-переменным) является следующим этапом.
> Секретные ключи (service_role) в клиентский код не добавлять — только anon key + RLS.

## Безопасность ребёнка

Нет чата, публичных профилей, рекламы, геолокации и автоматических платежей. Фотографии
хранятся только локально (IndexedDB) либо в приватном бакете Supabase в облачном режиме.
Ребёнок не может начислить себе монеты или подтвердить свои задания — только родитель.
Скрытие кнопок не является защитой: финансовые операции проверяются слоем бизнес-логики
(идемпотентность по `referenceId`, запрет минуса, статусные переходы заявок).

## PWA и офлайн

- `vite-plugin-pwa`: manifest, service worker, precache всех ресурсов, иконки SVG.
- Установка: в профиле появится «Установить на телефон» (при поддержке браузером)
  либо через меню браузера «Добавить на главный экран».
- Офлайн доступны альбом, «Это я!» и задания; операции с балансом проходят проверку
  перед применением. Индикатор «Локально/Онлайн/Офлайн» — в шапке главной.
- Уважается системная настройка `prefers-reduced-motion`; звук выключен по умолчанию.

## Установка на Xiaomi Redmi 14 (Android)

Вариант 1 — локально, без интернета после установки:
1. На компьютере: `npm run build && npm run preview -- --host`
   (покажет адрес вида `http://192.168.x.x:4173`).
2. Телефон должен быть в той же Wi-Fi сети → открыть адрес в Chrome.
3. Chrome: меню «⋮» → «Добавить на главный экран» → «Установить».
4. Приложение появится на рабочем столе и будет работать офлайн (PWA-кеш).

Вариант 2 — через интернет (мама и Соня с разных устройств):
1. Задеплойте сборку (`dist/`) на любой статический хостинг
   (Netlify, Vercel, GitHub Pages, Supabase Storage).
2. Откройте https-адрес на телефоне → «Добавить на главный экран».
3. Для синхронизации между устройствами настройте Supabase по инструкции выше.
   Пока облачный провайдер данных не подключён, каждое устройство живёт со своим
   локальным профилем.

## Графика: как получить «как в современных мобильных играх»

Текущие персонажи рисуются процедурным многослойным SVG с idle-анимациями (дыхание,
моргание, крылья, антенны, ауры редкости, блики и парение). Для настоящих художественных
иллюстраций в едином стиле:

1. **Генерация.** Используйте Midjourney, DALL-E, Recraft или Ideogram. Ключ к консистентности —
   один и тот же стилевой префикс во всех промптах, например:

   > `cute fantasy egg-pet character, soft 3D Pixar-like render, pastel purple and pink palette,
   > big sparkling eyes, chibi proportions, full body, centered, plain white background, sticker style`

   Генерируйте по одному персонажу на картинку, все с одинаковым префиксом.
2. **Фон.** Нужна прозрачность: Recraft и Ideogram умеют генерировать с прозрачным фоном,
   либо удалите фон через remove.bg / Photoshop.
3. **Формат.** 512×512 (или 1024), WebP с прозрачностью, до ~100 КБ на файл.
4. **Подключение.** Положите файлы в `public/assets/pets/<id питомца>.webp`
   (id смотрите в карточке питомца / демо-каталоге: `demo-01`, `demo-02`, …) и перечислите
   в `public/assets/manifest.json`:
   ```json
   { "demo-01": "pets/demo-01.webp", "demo-02": "pets/demo-02.webp" }
   ```
   Компонент `PetImage` автоматически подставит настоящую картинку вместо процедурного SVG —
   в коллекции, на главной и на экране питомца. Для наград используйте поле `imageUrl`
   (загрузка через родительскую панель), для «Моих питомцев» — фото с устройства.
5. **Анимации** останутся работать поверх: парение, появление, конфетти, вылет монет.
   Если позже захотите скелетную анимацию уровня Spine — берите библиотеку `pixi.js`
   или `@pixi/spine`, слоты под спрайты уже изолированы в `components/art.tsx`.

После `git push` GitHub Actions сам пересоберёт и опубликует новую версию (~40 секунд).
