# Входящие письма от дяди Ярика

Соня не открывает Telegram. Дядя Ярик отправляет обычный текст или голосовое **в личный чат своего бота**. Telegram передаёт сообщение приватной серверной функции, а игра проверяет почту при открытии и возвращении на экран.

Серверная функция принимает сообщения только от заданного Telegram user ID и хранит записи в приватном Supabase Storage/таблице. Старый токен бота, сохранённый на телефоне Сони, подтверждает право читать почту. В запросе браузер передаёт только SHA-256 proof; исходный токен в сборку GitHub Pages не попадает. При отсутствии токена его можно добавить в родительских настройках. Новых хранилищ IndexedDB и миграции прогресса нет.

## Подключение

1. Создать отдельный проект Supabase, открыть SQL Editor и выполнить `supabase/owl_mailbox.sql`.
2. Развернуть Edge Function `owl-mailbox` с `verify_jwt = false` из `supabase/config.toml`.
3. Задать секрет `TELEGRAM_BOT_TOKEN` (существующий бот). Служебный ключ Supabase функция получает из окружения платформы.
4. До задания `YARIK_TELEGRAM_ID` однократно открыть адрес функции с `?setup=1`: функция сама зарегистрирует Telegram webhook с секретом, производным от токена. Старый webhook этого бота, если был, будет заменён. Отправить боту `/id`: в ответ придёт числовой Telegram ID. Сохранить его как секрет `YARIK_TELEGRAM_ID`; после этого маршрут настройки закроется.
5. Добавить переменную GitHub Actions `INBOX_URL` с адресом функции. Публикация передаст её сборке как `VITE_INBOX_URL`.
6. Проверить на тестовом профиле: посторонний отправитель игнорируется, запрос без proof отвергается, текст и голосовое появляются в игре, уже прочитанное не вызывает новую плашку. Только после этого опубликовать обновление на основном адресе.

Если проект Supabase на бесплатном тарифе приостановится из-за неактивности, Telegram webhook временно перестанет принимать сообщения. Сервер нужно возобновить до повторной отправки. Голосовые ограничены 5 МБ. Функция не пересылает PIN, монеты, фото или другой игровой прогресс.
