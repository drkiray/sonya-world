# Подключение облачных копий

Игра и её прогресс продолжат работать локально. Этот отдельный проект Supabase хранит только копии.

1. Создать бесплатный проект на [Supabase](https://supabase.com/dashboard) в аккаунте взрослого. Сохранить пароль от аккаунта.
2. Открыть **SQL Editor**, выполнить [`supabase/backup_storage.sql`](../supabase/backup_storage.sql). Убедиться в **Storage**, что бакет `sonya-backups` приватный.
3. В **Authentication → Users** пригласить адрес взрослого, который будет использоваться на телефоне. Отключить публичную регистрацию в **Authentication → Providers → Email** после приглашения. В **Authentication → Email Templates → Magic Link** заменить ссылку в шаблоне на `{{ .Token }}`, чтобы приходил шестизначный код. Проверить доставку кода. При ограничениях встроенной почты Supabase настроить SMTP.
4. В **Project Settings → API** скопировать Project URL и публичный `anon`/publishable key в переменные репозитория GitHub Actions `BACKUP_SUPABASE_URL` и `BACKUP_SUPABASE_ANON_KEY`. Workflow передаёт их сборке как `VITE_BACKUP_SUPABASE_URL` и `VITE_BACKUP_SUPABASE_ANON_KEY`. Служебный `service_role` key туда не добавлять.
5. Проверить на тестовом профиле: вход по коду, создание снимка, дату в родительской панели, скачивание JSON, запрет чтения чужой папки, новую копию через 7 дней. Только после этого публиковать новую версию игры.
6. На телефоне Сонечки открыть родительские настройки и один раз войти по почтовому коду. Копии будут создаваться при открытии игры, если с предыдущей прошло семь дней. Если игра закрыта, отправка ждёт следующего открытия.

Снимки содержат фото и сведения о ребёнке. Доступ к аккаунту и скачанным файлам должен быть только у взрослого. Бесплатный проект Supabase может приостанавливаться при низкой активности; родительская панель показывает дату последней удачной копии и ошибку отправки. Из облачной копии исключены PIN и старые Telegram credentials. Автоматического восстановления нет, чтобы не затереть более свежий прогресс на телефоне.
