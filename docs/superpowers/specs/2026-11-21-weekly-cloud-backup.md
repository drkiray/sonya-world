# Еженедельная облачная копия прогресса

## Цель

Прогресс Сонечки остаётся в IndexedDB на текущем адресе GitHub Pages. Приложение автоматически сохраняет полный снимок на приватном сервере при первом открытии после семи дней. Взрослый видит дату последней копии и ошибки в родительской панели.

## Сервер и доступ

- Отдельный проект Supabase Storage с приватным бакетом `sonya-backups`. Он используется только для копий, не для игровой логики или монет.
- Взрослый один раз входит на телефоне Сони по коду из письма. После этого сессия сохраняется браузером. Ребёнку ничего настраивать не нужно.
- Доступ к файлам ограничен Supabase Auth и RLS: пользователь видит и создаёт файлы только в папке своего `auth.uid()`. Публичного чтения, перезаписи и удаления нет.
- В сборку входят только URL проекта и публичный ключ. Адрес почты, пароли и служебные ключи в коде не публикуются.

## Снимки

- Отправка проверяет дату последнего снимка на сервере. Если он старше семи дней или отсутствует, считывает все 10 существующих object stores и загружает новый JSON-файл. Старые снимки не удаляются автоматически.
- Копия содержит игровой прогресс и фото. Из `meta` исключаются родительский PIN и старые настройки Telegram. Исходные записи IndexedDB не изменяются.
- Первая копия создаётся сразу после подключения взрослым. Повторные проверки выполняются при открытии игры и при возвращении к ней, но не чаще одного раза в час. Сбой сети не мешает играть; новая попытка будет при следующем запуске.
- Если игра закрыта, браузер не может прочитать IndexedDB. Точная календарная отправка в закрытом состоянии невозможна; копия отправится при следующем открытии.
- В родительской панели видны статус, дата последней успешной копии и кнопка ручной проверки/отправки. Взрослый может скачать последнюю облачную копию.

## Сохранность

- Не менять текущий домен, PWA scope, имя и версию IndexedDB, `initStore` и игровые операции.
- Не публиковать обновление, пока проект Supabase, правила доступа и настоящая загрузка/скачивание не проверены.
- Восстановление в IndexedDB из облака не выполняется автоматически: оно может затереть актуальные локальные данные. При необходимости потребуется отдельное подтверждённое действие.
